# 매니저 사용자 관리 권한 연결

## 변경 범위

- 매니저: 사용자 관리 권한 ON일 때 자기 공장의 검사자 추가·프로필 수정·프로필 삭제 허용.
- 관리자: 기존 역할·공장 범위 유지.
- 매니저의 다른 공장 및 관리자·매니저 대상 작업은 허용하지 않음.
- `admin-create-user`가 service-role 호출 전에 역할·공장·기능 권한을 검사.
- 수정·삭제는 기존 authenticated RLS 경로 유지. 운영 users_update/users_delete 정책에서 같은 범위를 확인함.
- 화면 버튼과 역할·공장 선택을 동일 범위로 제한. ALV에서도 신규 공장을 ALT로 기본 지정하던 문제 수정.
- 삭제 결과 0행을 성공으로 알리지 않도록 단일 삭제 결과 확인.

## 검증

- `node --test tests/admin-create-user.test.cjs tests/user-delete.test.cjs`
- 생성 handler 원본을 실행하되 네트워크·Auth는 대역 처리: ALT/ALV 정상 생성, 기능 OFF, 조회 오류, 다른 공장, 상위 역할 생성, 검사자 호출, 인증 실패, 관리자 호환성 검증.
- 삭제 결과 확인 및 RLS 등으로 0행인 경우 실패 처리 검증.
- `npm run lint`, `npm run build`.
- 실제 계정 생성/수정/삭제 및 브라우저 E2E는 수행하지 않음.

## 운영 반영과 기존 한계

새 DB 마이그레이션은 필요하지 않다. 운영 적용에는 변경된 `admin-create-user` Edge Function과 프런트엔드 배포가 필요하다. 이번 작업에서 배포하지 않았다.

이번 변경은 기존 사용자 관리 기능의 역할 권한 연결이다. 기존 수정 서비스는 public.users 프로필을 수정하고, 삭제 서비스는 해당 프로필을 삭제한다. Auth 로그인 이메일·비밀번호 변경 및 Auth 계정 자체 삭제는 기존 서비스에서 지원하지 않으며 이번 변경에도 포함하지 않았다. 특히 기존 편집창의 비밀번호 입력은 저장 서비스가 처리하지 않는 별도 결함이다. 계정 자격 증명까지 포함한 CRUD 완료로 해석하지 않는다.

운영 확인 시 테스트 계정으로 자기 공장 검사자 추가→이름 수정→삭제를 확인하고, 권한 OFF·다른 공장·상위 역할 작업 거부를 확인한다.
